# Стандарт проекта
# Среда разработки

Версия: 1.0

Статус: Действует

---

# 1. Назначение

Настоящий документ определяет используемую среду разработки проекта, технологический стек и правила работы с окружением.

Все изменения должны учитывать данную конфигурацию.

---

# 2. Общая архитектура

Проект является внутренней корпоративной системой.

Особенности:

- отсутствует публичный доступ из сети Интернет;
- используется единое рабочее окружение;
- отсутствует разделение на Development / Test / Production;
- разработка и эксплуатация выполняются на одном экземпляре системы.

Любые изменения должны учитывать данную особенность.

---

# 3. Серверная платформа

Операционная система:

- Debian 12

Веб-сервер:

- Nginx

PHP:

- PHP 8.4

База данных:

- PostgreSQL 16

---

# 4. Framework

Используется:

- Yii2 Advanced Template

При разработке необходимо придерживаться архитектурных принципов Yii2.

Запрещается нарушать существующую структуру приложения без предварительного согласования.

---

# 5. Frontend

Используются:

- Bootstrap
- JavaScript
- jQuery
- HTML5
- CSS3
- SCSS

Сборка ресурсов выполняется средствами проекта.

---

# 6. Backend

Основной язык:

- PHP 8.4

Основные принципы:

- строгая типизация;
- использование сервисного слоя;
- минимизация логики в контроллерах;
- использование ActiveRecord только по назначению;
- бизнес-логика должна находиться в сервисах.

---

# 7. База данных

Используется PostgreSQL.

Структура базы данных считается частью архитектуры проекта.

Изменение структуры допускается только посредством миграций.

Любые изменения предварительно согласовываются.

---

# 8. Система контроля версий

Используется Git.

Каждый завершённый этап разработки сопровождается отдельным коммитом.

Не допускается накопление большого количества несвязанных изменений в одном коммите.

---

# 9. Принцип разработки

Работа выполняется исключительно малыми этапами.

Каждый этап должен:

- иметь одну цель;
- иметь минимальный объём изменений;
- легко проверяться;
- легко откатываться.

---

# 10. Проверка изменений

После каждого этапа выполняется:

1. генерация изменений;
2. внедрение;
3. проверка;
4. исправление ошибок;
5. повторная проверка;
6. коммит.

Только после успешной проверки допускается переход к следующему этапу.

---

# 11. Архитектура проекта

При разработке используется сервисная архитектура.

Основные требования:

- разделение ответственности;
- отсутствие дублирования кода;
- высокая расширяемость;
- использование интерфейсов;
- минимальная связанность компонентов.

---

# 12. Подсистема Output

Во всех новых компонентах проекта используется единая подсистема Output.

Запрещается использовать:

- echo;
- print;
- printf;
- stdout;
- stderr;
- Yii::info();
- Yii::warning();
- Yii::error();

Все сообщения проходят через OutputInterface.

---

# 13. Документирование

Обязательными являются:

- комментарии к публичным методам;
- архитектурные решения (ADR);
- стандарты проекта;
- техническая документация.

Документация является частью результата разработки.

---

# 14. Рефакторинг

Любой рефакторинг выполняется:

- поэтапно;
- с обязательной проверкой каждого этапа;
- без одновременного изменения нескольких независимых подсистем.

При обнаружении архитектурной проблемы допускается временная остановка текущего рефакторинга для устранения проблемы инфраструктуры проекта.

---

# 15. Требования к новому коду

Новый код должен:

- соответствовать действующей архитектуре;
- использовать существующие сервисы;
- использовать существующие интерфейсы;
- не дублировать функциональность;
- быть расширяемым без модификации существующих компонентов.

---

# 16. Приоритет

При возникновении противоречий приоритет документов определяется следующим образом:

1. Конституция проекта;
2. Настоящий стандарт;
3. Остальные стандарты проекта;
4. ADR;
5. Исходный код.

Любые изменения среды разработки должны сопровождаться актуализацией настоящего документа.
