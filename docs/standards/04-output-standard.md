# Стандарт проекта
# Подсистема Output

Версия: 1.0

Статус: Действует

---

# 1. Назначение

Подсистема Output предназначена для унифицированного вывода сообщений всеми компонентами проекта.

Основные задачи:

- исключить прямую зависимость сервисов от способа вывода;
- обеспечить единый формат сообщений;
- обеспечить возможность смены способа вывода без изменения бизнес-логики;
- обеспечить тестируемость сервисов.

---

# 2. Основной принцип

Ни один сервис проекта не должен знать, каким способом выводится информация.

Сервис взаимодействует исключительно с интерфейсом:

```
OutputInterface
```

---

# 3. Архитектура

Подсистема строится по следующей схеме:

```
                OutputInterface
                      │
        ┌─────────────┼─────────────┐
        │             │             │
 ConsoleOutput   YiiLogOutput   NullOutput
        │             │             │
        └─────────────┼─────────────┘
                      │
               OutputFormatter
```

---

# 4. OutputInterface

Интерфейс определяет единый контракт вывода сообщений.

Минимальный набор методов:

- info()
- success()
- warning()
- error()
- debug()

При необходимости интерфейс может быть расширен без изменения существующих сервисов.

---

# 5. OutputFormatter

OutputFormatter отвечает исключительно за форматирование сообщений.

Форматирование не должно зависеть от конкретного способа вывода.

Пример:

```
[ OK ] Printer found
```

или

```
[ERROR] Connection timeout
```

или

```
[WARN] Device not responding
```

Форматирование выполняется посредством enum и конструкции match.

Использование switch запрещается.

---

# 6. ConsoleOutput

ConsoleOutput предназначен для вывода сообщений в консоль.

Особенности:

- использует OutputFormatter;
- выводит сообщения через stdout/stderr;
- не содержит бизнес-логики;
- не выполняет форматирование самостоятельно.

---

# 7. YiiLogOutput

YiiLogOutput предназначен для записи сообщений в систему логирования Yii.

Использует:

- Yii::info()
- Yii::warning()
- Yii::error()

Никакой сервис проекта не должен обращаться к этим методам напрямую.

---

# 8. NullOutput

NullOutput используется в случаях, когда вывод сообщений не требуется.

Все методы выполняются без каких-либо действий.

Использование NullOutput избавляет сервисы от необходимости проверять:

```
if ($output !== null)
```

---

# 9. Контекст сообщений

Все методы Output должны поддерживать передачу контекста.

Пример:

```php
$output->error(
    'SNMP unavailable',
    [
        'ip' => $ip,
        'deviceId' => $device->id,
    ]
);
```

Контекст используется реализацией Output по своему усмотрению.

ConsoleOutput может вывести его в читаемом виде.

YiiLogOutput может сериализовать его в JSON.

---

# 10. Уровни сообщений

Поддерживаются следующие уровни:

- DEBUG
- INFO
- SUCCESS
- WARNING
- ERROR

Допускается расширение перечня без изменения существующих сервисов.

---

# 11. Dependency Injection

OutputInterface передаётся сервисам через конструктор.

Пример:

```php
public function __construct(
    OutputInterface $output = new NullOutput()
)
```

Сервисы не создают ConsoleOutput или YiiLogOutput самостоятельно.

Выбор конкретной реализации выполняет вызывающий код.

---

# 12. Ответственность

Output отвечает исключительно за вывод информации.

Output не должен:

- выполнять бизнес-логику;
- обращаться к базе данных;
- изменять состояние объектов;
- принимать архитектурные решения.

---

# 13. Запрещённые действия

Во всём проекте запрещается использовать напрямую:

```
echo
print
printf
var_dump
print_r

Controller::stdout()
Controller::stderr()

Yii::info()
Yii::warning()
Yii::error()
```

Все подобные обращения должны выполняться через OutputInterface.

---

# 14. Расширяемость

Подсистема должна позволять без изменения существующего кода добавлять новые реализации.

Например:

- FileOutput
- JsonOutput
- SyslogOutput
- TelegramOutput
- EmailOutput
- WebSocketOutput

Добавление новой реализации не должно требовать изменения сервисов.

---

# 15. Архитектурный принцип

Подсистема Output реализует принцип Dependency Inversion.

Высокоуровневые сервисы зависят исключительно от OutputInterface.

Конкретные реализации являются деталями инфраструктуры.

---

# 16. Обязательное применение

Все новые сервисы проекта обязаны использовать исключительно OutputInterface.

Использование любых альтернативных способов вывода считается нарушением архитектурного стандарта проекта.
