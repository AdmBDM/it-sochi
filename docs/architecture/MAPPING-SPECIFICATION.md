# Mapping Specification

Версия: 1.0

Статус: Accepted

Дата: 2026-07-22

---

# Назначение

Настоящий документ определяет правила переноса существующих справочников в новую подсистему Master Data.

Документ является обязательной инструкцией при разработке миграций переноса данных.

Создание новой структуры и перенос данных являются независимыми этапами.

Удаление старых таблиц допускается только после полного завершения переноса и перехода всех компонентов проекта на новую архитектуру.

---

# Общие правила

## Последовательность

Для каждого справочника используется единый порядок действий:

1. Создание новой структуры.
2. Создание модели ActiveRecord.
3. Перенос данных.
4. Адаптация сервисов.
5. Адаптация пользовательского интерфейса.
6. Проверка работоспособности.
7. Удаление старой структуры.

---

## Временные поля соответствия

При необходимости допускается создание временных полей соответствия.

Пример

```
legacy_id
```

Назначение

Хранение идентификатора исходной записи.

Используется исключительно на этапе миграции.

После завершения перехода временные поля удаляются отдельной миграцией.

# Карта соответствия

---

## device_types

Исходная таблица

```
device_types
```

Новая таблица

```
classifiers
```

Корневой классификатор

```
device_types
```

Перенос

Все записи становятся дочерними элементами корневого узла
`device_types`.

---

## device_brands

Исходная таблица

```
device_brands
```

Новая таблица

```
vendors
```

Перенос

Каждый производитель создаётся как самостоятельная запись.

Иерархия отсутствует.

---

## device_models

Исходная таблица

```
device_models
```

Новая таблица

```
catalog_items
```

Перенос

Модели становятся элементами каталога.

Родитель определяется структурой каталога.

Связь с производителем осуществляется через `vendor_id`.

---

## buildings

Исходная таблица

```
buildings
```

Новая таблица

```
space_objects
```

Тип объекта

```
building
```

Перенос

Каждое здание становится корневым пространственным объектом.

---

## departments

Исходная таблица

```
departments
```

Новая таблица

```
space_objects
```

Тип объекта

```
block
```

или иной тип согласно классификатору пространственных объектов.

Перенос

Подразделения размещаются внутри соответствующего здания.

Итоговая иерархия определяется пространственной моделью предприятия.

---

## locations

Исходная таблица

```
locations
```

Новая таблица

```
space_objects
```

Тип объекта

Определяется классификатором.

Например

```
floor

room

workplace
```

Перенос

Объекты включаются в соответствующую пространственную иерархию.

---

## organizations

Исходная таблица

```
organizations
```

Новая таблица

```
organization_objects
```

Тип объекта

```
organization
```

Перенос

Организации становятся корневыми элементами организационной структуры.

---

# Таблицы, не участвующие в переносе

Настоящий этап не затрагивает

```
devices

employees

movements

users

printer_page_counters

discovered_devices

...
```

Они будут адаптироваться после завершения формирования новой Master Data.

---

# Порядок удаления старых таблиц

Удаление допускается только после выполнения всех условий:

- данные полностью перенесены;
- ActiveRecord переведены;
- сервисы используют новую структуру;
- API использует новую структуру;
- Discovery использует новую структуру;
- пользовательский интерфейс использует новую структуру;
- отсутствуют ссылки на старые таблицы.

Удаление выполняется отдельными миграциями.

---

# Контроль завершения

Рефакторинг считается завершённым после выполнения следующих условий:

- все новые таблицы созданы;
- все справочники перенесены;
- все сервисы используют новую структуру;
- все модели используют новую структуру;
- старые таблицы удалены;
- временные поля соответствия удалены;
- документация актуализирована.

---

# Статус

Настоящий документ является обязательной спецификацией для миграций переноса данных.

Любые изменения порядка или правил переноса допускаются только после изменения настоящего документа.
