# MDM-0001

# Master Data Model

Версия: 1.0

Статус: Accepted

Дата: 2026-07-22

---

# Назначение

Настоящий документ определяет единую модель мастер-данных проекта.

Все последующие миграции, модели ActiveRecord, сервисы, Discovery, импорт, API и пользовательский интерфейс обязаны использовать исключительно настоящую модель.

Настоящий документ является основным источником истины для структуры мастер-данных проекта.

---

# Общая модель

Подсистема мастер-данных состоит из пяти основных сущностей.

```
                 classifiers
                      │
                      │
      ┌───────────────┼───────────────┐
      │               │               │
      │               │               │
catalog_items   space_objects   organization_objects
      │
      │
   vendors
```

---

# Сущности

## 1. classifiers

Назначение

Хранение всех иерархических классификаторов проекта.

Особенности

- единая таблица;
- модель хранения "лес";
- каждый классификатор является корневым узлом;
- дочерние элементы образуют дерево.

Примеры корневых узлов

```
device_types

space_object_types

organization_object_types
```

Ответственность

- типы устройств;
- типы пространственных объектов;
- типы организационных объектов;
- будущие классификаторы проекта.

---

## 2. vendors

Назначение

Хранение производителей оборудования.

Примеры

```
HP

Dell

Brother

Kyocera

Cisco

MikroTik
```

Особенности

Справочник является плоским.

Иерархия отсутствует.

---

## 3. catalog_items

Назначение

Единый каталог оборудования.

Особенности

Иерархическая структура.

Типичная схема

```
HP
    LaserJet
        M404dn
        M428fdw

Dell
    OptiPlex
        7090
```

Ответственность

Описание каталога оборудования.

Каталог не содержит конкретных устройств.

---

## 4. space_objects

Назначение

Единая пространственная модель предприятия.

Иерархическая структура.

Типичный пример

```
Здание

    Блок

        Этаж

            Помещение

                Рабочее место
```

Заменяет

```
buildings

departments

locations
```

Ответственность

Описание физических объектов предприятия.

---

## 5. organization_objects

Назначение

Организационная структура предприятия.

Иерархическая структура.

Типичный пример

```
Организация

    Управление

        Отдел

            Сектор
```

Ответственность

Описание организационной структуры.

Не содержит пространственных данных.

---

# Принципы моделирования

---

## Пространственная модель независима

Физическое расположение объектов описывается исключительно

```
space_objects
```

---

## Организационная модель независима

Организационная структура описывается исключительно

```
organization_objects
```

---

## Производители отделены от каталога

Производитель является самостоятельной сущностью.

Каталог оборудования использует ссылку на производителя.

---

## Классификаторы независимы от каталогов

Тип оборудования определяется классификатором.

Каталог оборудования не является классификатором.

---

## Все иерархии используют одинаковую модель

Любая древовидная сущность использует одинаковую архитектуру.

```
parent_id
```

является единственным механизмом построения дерева.

---

# Что не относится к Master Data

Следующие сущности не являются мастер-данными.

```
devices

employees

movements

printer_page_counters

discovered_devices

users

...
```

Они используют Master Data, но не входят в неё.

---

# Общая схема зависимостей

```
classifiers
    │
    ├───────────────┐
    │               │
    │               │
space_objects   organization_objects

vendors
    │
    │
catalog_items

    │
    ├──────────────► catalog_items
    │
    ├──────────────► space_objects
    │
    ├──────────────► organization_objects
    │
    └──────────────► classifiers
```

# Правила развития

Добавление нового классификатора выполняется добавлением нового корневого узла.

Добавление нового производителя не требует изменения структуры БД.

Добавление нового каталога выполняется созданием новых узлов дерева.

Добавление нового пространственного объекта выполняется созданием нового узла дерева.

Добавление нового организационного объекта выполняется созданием нового узла дерева.

Изменение структуры таблиц для расширения модели не допускается.

Расширение модели должно выполняться исключительно добавлением данных.
