# Migration Roadmap

Версия: 1.0

Статус: Accepted

Дата: 2026-07-22

---

# Назначение

Настоящий документ определяет единственную допустимую последовательность выполнения рефакторинга подсистемы Master Data.

Изменение порядка этапов допускается только после изменения настоящего документа.

Каждый этап должен быть полностью завершён, протестирован и зафиксирован отдельным коммитом перед переходом к следующему.

---

```
classifiers
```

## 1.3

Создать таблицу


Назначение

Единый каталог оборудования.

---

## 1.4

Создать таблицу

```

```

Назначение

Единая пространственная модель.

---

## 1.5

Создать таблицу

```
organization_objects
```

После завершения этапа

- проверить применение миграций;
- проверить откат миграций;
- выполнить коммит.

# Этап 2. Заполнение базовой структуры

Создать корневые элементы классификаторов.

Минимальный состав

```
device_types

space_object_types

organization_object_types
```

При необходимости добавить остальные классификаторы, уже используемые проектом.

После завершения выполнить коммит.

# Этап 4. Адаптация моделей

Последовательно перевести ActiveRecord-модели на новую структуру.

Порядок определяется зависимостями.

После завершения выполнить коммит.

---

# Этап 5. Адаптация сервисов

Последовательно перевести

- Discovery;
- SNMP;
- импорт;
- API;
- внутренние сервисы.

Каждая подсистема завершается отдельным коммитом.

---

# Этап 6. Адаптация пользовательского интерфейса

Перевести формы.

Перевести справочники.

Перевести GridView.

Перевести фильтры.

После завершения выполнить коммит.

---

# Этап 7. Перенос рабочих данных

Последовательно перевести существующие рабочие сущности на новую структуру.

Пример

```
devices

employees

workplaces

movements
```

Порядок определяется зависимостями.

После завершения выполнить коммит.

---

# Этап 8. Удаление старой структуры

Удаляются только те таблицы, которые полностью выведены из эксплуатации.

Удаление допускается только после проверки отсутствия зависимостей.

Удаление выполняется отдельными миграциями.

После завершения выполнить коммит.

---

# Общие правила

Каждая миграция должна:

- полностью соответствовать PDM-0001;
- быть атомарной;
- иметь корректный safeDown();
- создавать все необходимые индексы;
- создавать триггер `update_updated_at_column()`;
- использовать единый стандарт внешних ключей;
- быть полностью работоспособной без последующих исправлений.

---

# Правила разработки

Запрещается

- объединять несколько логических этапов в одну миграцию;
- изменять утверждённую архитектуру;
- выполнять перенос данных одновременно с созданием структуры;
- удалять старые таблицы до завершения переноса.

Обязательно

- один логический этап — одна миграция;
- один завершённый этап — один коммит;
- переходить к следующему этапу только после успешного тестирования предыдущего.

---

# Статус

Настоящий документ определяет обязательную последовательность реализации рефакторинга подсистемы Master Data.

Любые отклонения от указанного порядка должны быть оформлены отдельным ADR.
