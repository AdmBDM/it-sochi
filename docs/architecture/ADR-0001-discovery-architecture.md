# ADR-0001. Архитектура подсистемы Discovery

## Статус

Принято.

## Дата

2026-07-21

---

# Контекст

Подсистема Discovery предназначена для автоматического обнаружения устройств
в сети предприятия с последующей идентификацией и передачей результатов
в подсистему инвентаризации.

Подсистема должна быть независимой от конкретных протоколов,
типов оборудования и способов хранения данных.

Основными требованиями являются:

- расширяемость;
- минимальная связанность компонентов;
- соответствие SOLID;
- возможность добавления новых Scanner и Probe без изменения существующего кода.

---

# Решение

Архитектура строится как последовательный конвейер обработки.

```
Scanner
    ↓
NetworkNode
    ↓
DeviceDetector
    ↓
DeviceProbe
    ↓
DiscoveredDevice
    ↓
InventoryManager
    ↓
Repository
```

Каждый компонент отвечает только за собственную область ответственности.

---

# Основные компоненты

## Scanner

Отвечает исключительно за обнаружение сетевых узлов.

Результатом работы Scanner является объект NetworkNode.

Scanner не определяет тип устройства.

Scanner не содержит бизнес-логики.

---

## NetworkNode

DTO обнаруженного сетевого узла.

Содержит только информацию,
полученную непосредственно во время обнаружения.

---

## DeviceDetector

Определяет Probe,
способный обработать обнаруженный узел.

Detector не содержит логики идентификации устройств.

---

## DeviceProbe

Выполняет идентификацию устройства.

Результатом работы Probe является объект DiscoveredDevice.

Каждый Probe отвечает только за собственный тип устройств.

---

## DiscoveredDevice

DTO идентифицированного устройства.

Содержит сведения,
необходимые для дальнейшей обработки системой инвентаризации.

---

## InventoryManager

Получает DiscoveredDevice
и передаёт его в подсистему хранения.

Не содержит логики обнаружения устройств.

---

## Repository

Отвечает исключительно за сохранение результатов обнаружения.

---

# Реестры

Используются два реестра.

## ScannerRegistry

Хранит зарегистрированные Scanner.

## DeviceProbeRegistry

Хранит зарегистрированные Probe.

Регистрация выполняется один раз при инициализации приложения.

---

# Dependency Injection

Все зависимости передаются через конструкторы.

Компоненты взаимодействуют исключительно через интерфейсы.

Непосредственное создание зависимостей внутри компонентов запрещено.

---

# DTO

Используются два независимых DTO.

## NetworkNode

Используется только между Scanner и Probe.

## DiscoveredDevice

Используется после идентификации устройства.

DTO не содержат бизнес-логики.

---

# Принципы

Подсистема строится на следующих принципах.

- Single Responsibility Principle.
- Dependency Inversion Principle.
- Open/Closed Principle.
- Композиция предпочтительнее наследования.
- Scanner обнаруживает узел.
- Probe идентифицирует устройство.
- Detector выбирает Probe.
- Repository отвечает только за сохранение.

---

# Последствия

Архитектура позволяет независимо развивать:

- новые Scanner;
- новые Probe;
- новые способы хранения данных;
- новые источники диапазонов IP;
- новые транспортные протоколы.

Добавление нового оборудования не требует изменения существующих компонентов.

Подсистема остаётся расширяемой без нарушения существующей архитектуры.
